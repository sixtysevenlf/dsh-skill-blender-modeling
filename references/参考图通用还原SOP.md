# 参考图通用还原 SOP（与对象类别无关）

> 配套：插件 `shape_*` 家族（方法层）+ `img_*`/`vehicle_*`（量具与几何）。
> 一句话：**几何机制与类别无关**——量轮廓 → 放样 → 特征线 → IoU 验收；换类别只换协议（视图/比例/验收门）。

## 0. 适用与不适用

| | 对象 |
|---|---|
| **适用** | 有明确外轮廓、能用正交视图描述的：车辆 / 人形 / 动物 / 家具 / 头盔 / 船体 / 飞机 / 枪械 / 道具 |
| **需变体** | 轴对称（→ `shape_revolve`）/ 多体量（→ `shape_regions`）/ 只做一半（对称件）/ 柔性但成形（坐垫） |
| **不适用** | 没有外轮廓的（布料 / 毛发 / 流体 / 烟）/ 靠内部结构定义的（多孔晶格 / 拓扑优化件） |

## 1. 八步（每步都有数字）

| 步 | 动作 | 算子 | 产出/判据 |
|---|---|---|---|
| ① | 校正 | `img_rectify`（四角单应，纯 numpy） | 正交图 + `mm_per_px`；**照片必做**，但只对"取点那个平面"成立（见 §3.1） |
| ② | 量包络 | 先看 `shape_plan(object_class=…)` 拿该类关键比例 | 长/宽/高 + 类别比例；**不过比例门别往下做** |
| ③ | 量站表 | `shape_sections`（侧视逐列上下边界 + 俯视半宽 + 前视截面轮廓） | `stations[]` + `section_shape[]` + `package` |
| ④ | 放样 | `shape_loft` | 站表定轮廓、截面轮廓定性格 |
| ⑤ | 特征线 | `crease_lines`（硬折线 / `radius_mm` 真圆角）+ `inset_lines`（折面凹槽） | 面感参数化 |
| ⑥ | 参数化（可选） | `shape_fit`（折线族 + K 扫描） | 可改数字的 spec；**族外形状 IoU 会卡在 ~0.82** |
| ⑦ | 多体量/缝 | `shape_regions` / `shape_panels` | 每块一个体量；缝是真几何（可 `clear_check` 量） |
| ⑧ | 验收 | `qc_render_views(ortho, ref_path)` / `img_diff` + `clear_check` + `audit_mesh` | **每个视图各自 IoU** + 尺寸/比例/间隙数字（IoU 只判轮廓，见 §4） |

## 1.5 三个扩展（2026-09-26 新增）

| 需求 | 用什么 | 说明 |
|---|---|---|
| **翼型 / 带弯度 / 左右不对称截面** | `vehicle_loft(section_outline=[[y_mm,z_mm],…])` | 显式闭合轮廓按站点归一（y 按半宽、z 按站高）；`section_source=custom_outline`。前视逐行宽度那条路**必然左右对称**，翼型必须走这条 |
| **旋转体 + 多体量装配**（轮毂+轮胎、瓶身+瓶盖、喷口阵列） | `shape_revolve(parts=[{profile, at:[x,y,z]_mm, name}])` | 每件独立对象 + 独立落点；装配后照旧用 `clear_check` 验间隙 |
| **圆角的"方/凹"控制（G2 近似）** | `crease_lines` 条目加 `profile` | 0.5 = 正圆；>0.5 偏方（更接近 G2 平顺过渡）；<0.5 偏凹。回执 `bevel.profile` |

### 选哪条截面通路（决策规则，`shape_plan` 随协议返回）

1. **轴对称**（瓶/罐/轮毂/花瓶/喷口）=> `shape_revolve` —— **不要**用放样
2. **左右对称 + 前视有轮廓** => `section_shape`（归一化逐行宽度，按站点半宽缩放）
3. **有弯度 / 左右不对称 / 要精确控制截面**（翼型、机匣、异形件）=> `section_outline`（显式闭合轮廓）
4. **只有一条侧视轮廓、截面随长度基本不变**（板件、型材）=> 超椭圆 `section_pts` + 特征线即可
5. **多体量** => `shape_regions` / `shape_revolve(parts=[...])`，装配后 `clear_check` 验间隙

> 每类的 `section_path` 由 `shape_plan(object_class=...)` 直接给出，不用回头翻 CHANGELOG。

## 2. 类别协议（`shape_plan` 直接给）

| 类别 | 视图 | 关键比例 | 主力算子 | 主要坑 |
|---|---|---|---|---|
| vehicle | s f t | WBR / 轴距比 / 高长比 / 轮距比 / 前后悬 | `vehicle_package` `vehicle_loft` `clear_check` | 轮径不可从轮廓反推；没俯视图车身偏窄 |
| humanoid | s f | 头身比 7–8 / 肩宽≈1.5 头高 | `human_base` `human_head` `motion_joints` | 写实脸做不到 → 面罩遮 |
| creature | s f t | 身长/肩高 / 头长/身长 | `shape_loft` | 四足≠双足比例；毛发不适用 |
| headwear | s f t | 头高:宽:深 ≈ 233:175:206；眼线 0.50/鼻底 0.725/嘴线 0.825 | `human_head` `face_ratios` | 内腔留头围余量 |
| furniture | s f | 座高/座深/靠背倾角 | `shape_regions` `sweep_build` | 人体工学优先于外形相似 |
| hull | s t | 船长/船宽/型深 | `shape_loft` | **水线上下要分别给站表** |
| aircraft | s f t | 翼展/机身长 / 弦长分布 | `shape_regions` `sweep_build` | 机翼用**翼型截面**不是超椭圆 |
| rotational | s（单轮廓） | 高/直径 / 最大直径位置 | `shape_revolve` | **别用放样** |
| weapon | s t | 总长 / 握把位置 | `shape_regions` `clear_check` | 握持尺寸是硬约束 |
| generic | s f（+t） | 先量三包络比 | `shape_sections` `shape_loft` `img_diff` | 照片先校正 |

## 3. 三个决定性细节（都是实测踩出来的）

1. **没有俯视图就没有平面收放**：只有侧+前视时 `half_w_mm` 缺失，车身会窄成 460mm（应 1850mm）；现在会用"前视最大宽 × 收放假设"回填并在回执标注假设来源。
2. **轮径/接地体不能从填充轮廓反推**（轮与车身连成一片）；但**轮轴位置可以**（轮廓底部低洼段聚类）。
3. **特征线不能按 z 带匹配边**（环上顶点离散，目标高度常常没有边 → 0 命中）；要用**环索引**；横向特征线还要**自动插站**。

### 3.1 `img_rectify` 的能力边界：单应只校正一个平面（★）

四点单应对**恰好落在取点那个物理平面**上的点严格成立；离开该平面的点误差随深度迅速放大。
实测（在 z=0 平面拟合单应；该机位 1 m ≈ 190 px）：

| 点离 z=0 平面的距离 | 最大误差 | 折算 |
|---|---|---|
| 0 m | **0.000 px** | 0 mm |
| 0.05 m | 9.906 px | **52 mm** |
| 0.20 m | 40.194 px | **211 mm** |
| 0.50 m | 103.464 px | **543 mm** |

⇒ **平面参考**（图纸翻拍 / 标定板 / 贴平的贴纸 / 地面标定框）完全正确；
**立体物**（车 / 人 / 建筑 / 头盔）只有取点那个平面准 —— 轮眉外扩、翼子板弧度、A 柱前倾、
鼻锥纵深这些**离平面远**的特征，量出来是错的。要么只量靠近该平面的尺寸，
要么改走真正的相机标定（内参 + 外参，多视几何），**不是**单应。

### 3.2 跨深度的误差不是 ±5%

透视下比例随深度按 `1/z` 变化，误差上界可算：`err ≈ Δz / (D + Δz)`（`D` = 相机到近处标尺距离，`Δz` = 深度差）。
实测（D = 8 m）：`Δz=0.5m → −5.88%`；`Δz=1m → −11.1%`；`Δz=3m → −27.3%` —— 与解析式逐行吻合。
⇒ **只跨 0.5 m 就已超出 ±5%**。估不出 `D` / `Δz` 就记 `unresolved`，别写"±5% 应该够"。

## 4. 验收纪律

- **数值门自己跑**（`audit_*` / `qc_*` / `clear_check` / `img_diff`）：脚本判据，不需要模型；回执大就 `summary_only:true` / `top_k:N`。
- **只有主观项**（"这个面感对不对"）才需要陌生视角；给它 `references/验收清单.md`，别给整本 SKILL.md。
- **每个视图的 IoU 分开算**：侧视最容易先到 0.9+，顶视最难（平面收放全靠它）。
- ★ **IoU 只是"该视图下轮廓重合度"**，是**必要不充分**条件。它**看不见**：深度/厚度、内部特征
  （板缝/格栅/灯/面罩/特征线位置）、曲面张力（面感）、其他视图、体积分布。而且"把轮廓填满"就能刷高它。
  ⇒ IoU 达标**只能推翻"轮廓错"**，不能证明"像"；必须配 `clear_check` 间隙 + `audit_measure` 尺寸 + 特征线对照。
  **别把 `target_iou` 当交付目标去凑。**
- **IoU 到不了就回看是哪一层错**：包络错（比例门挂）→ 改包络；轮廓错（侧视 IoU 低）→ 改站表；面感错（IoU 高但看着不对）→ 改特征线/圆角。
